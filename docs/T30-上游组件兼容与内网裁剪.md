## 2. 两个记忆补丁继续保留

- **Harness**：上游 `1.0.11` 缺少 `set_memory_access`、记忆读工具的动态访问检查和 `project_memory_messages`。Colink 依赖这些能力隔离共享专家与私人记忆，并从模型上下文和会话压缩中排除旧记忆副本。缺少隔离能力时，Colink 拒绝共享专家（`SHARED_MEMORY_ISOLATION_UNAVAILABLE`）。因此保留 `colink-harness[all]==1.0.7.post1`。
- **Memory**：上游 `1.0.5` 缺少 `forget_atom` 和 `atom_forget_ids`，无法执行 Colink 所需的永久遗忘或提供历史替换链 ID。Colink 另行持久化这些 ID，供备份恢复时过滤已遗忘记录。因此保留 `colink-memory==1.0.3.post1`。

继续使用 `octop` 导入名和命令。候选替换保持阻塞，直到上游提供等效能力，并用新版数据验证实际隔离和删除。

| 测试 | 已验证 | 边界 |

## 4. 内网裁剪与启动

| 对象 | 当前实现与部署条件 |
| --- | --- |
| SkillHub 公开技能市场 | 公开市场 HTTP 路由由 `_offline_only` 拒绝；底层未配置 `SKILL_MARKET_ORIGIN` 或 `SKILLSET_ORIGIN` 时仍指向 `api.skillhub.cn`。不得用底层默认地址判断路由是否开放。 |
| Octop Portal 专家市场 | 公共市场路由要求离线审核。首次引导也可能尝试从 Portal 获取默认专家，因此离线容器显式设置 `OCTOP_PORTAL_ORIGIN=`；未设置时默认是 `octop.cloud`。 |
| 需公网登录的连接器 | 保留目录和 OAuth 入口。内网部署不创建公网连接器实例、不为专家绑定这些实例；首次启动不需要配置公网 OAuth。未逐一验证外部服务。 |
| 云主机控制 | 上游 b7 含 `tencent-cvm-ops` 专家库和 `tencentcloud-sdk-python` 依赖；Colink 当前源码和锁文件未采用，内网交付不启用云主机控制。 |
| 远端对象存储 | COS、S3、OBS、TOS 属于另行配置的远端存储能力；本次启动使用本地配置，未配置或调用远端存储。 |
| 核心 Gateway | 保留本地设备接入与 WebSocket。空目录集成测试覆盖 SQLite 绑定、管理账号、设备审批及重启持久化；HTTP 与 WebSocket 客户端均在进程内运行。 |

在 macOS ARM64 用系统沙箱禁止服务进程出网，设置 `OCTOP_PORTAL_ORIGIN=`，从空的临时 `OCTOP_HOME` 运行 `octop run`。本机 `/api/health` 返回 HTTP 200、`db=false`，安装向导凭据文件已生成；同一出网限制下，`tests/integration/test_offline_deployment_api.py` 通过。本次没有安装目标平台发行包，也没有接入公网连接器或消息平台。

## 5. 许可、裁剪与资源

- 核对四个上游候选包的校验值及根许可证。上游 Harness `1.0.11` 和实际采用的 `colink-harness 1.0.7.post1` **各含 51 个**受限 PowerPoint 技能文件，带独立许可证及 Anthropic 版权声明；组件根 MIT 许可不覆盖这套材料。
- 分别解包两份真实 Harness wheel，在暂存安装树运行 `scripts/strip_restricted_skills.py`：PPT 文件与安装清单中的对应记录均归零，根许可证保留。裁剪脚本的回归由 `tests/unit/test_release_skill_materials.py` 覆盖。
- 便携包、容器和 FnOS 原生包的裁剪入口见 [T01 发行材料与许可处置](T01-源码许可与麒麟早期核验.md#2-发行材料与许可处置)。本次未复查最终产物；直接通过 Python 安装仍会拉取包含受限文件的 Harness wheel，该渠道尚未解决。
- Browser wheel 包含录制脚本，不包含离线所需的浏览器二进制。最终交付仍需核对浏览器、系统库、字体等随包资源及其许可证。
