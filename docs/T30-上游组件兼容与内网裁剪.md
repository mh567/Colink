## 2. 两个现有 Colink 补丁保留评估与阻塞记录

对上游 `octop-harness 1.0.11` 与 `octop-memory 1.0.5` 候选包进行反编译与模块检测，核对 Colink 现有两大安全与合规能力：

### 2.1 Harness 补丁 (`colink-harness`)

1. **共享专家记忆动态隔离**：
   - Colink 依赖 `HarnessAgentConfig.memory_access_enabled`、`HarnessAgent.set_memory_access(enabled)` 以及 `memory_tools` 动态门禁 `access_allowed()`，确保共享专家无法读取普通员工的私有结构化记忆。
   - 上游 1.0.11 核验结果：`set_memory_access` 缺失 (`False`)，`access_allowed` 缺失 (`False`)，`MEMORY_READ_TOOLS` 缺失 (`False`)。
2. **上下文投影防污染**：
   - Colink 通过 `project_memory_messages` 排除模型调用和会话压缩中的旧记忆副本，避免派生文本污染新回合。
   - 上游 1.0.11 核验结果：`project_memory_messages` 缺失 (`False`)。
3. **受限材料剥离**：
   - 上游 1.0.11 仍内嵌 51 个受限非商业许可证的 PowerPoint 技能文件。
- **结论与阻塞理由**：若直接替换为上游 1.0.11，共享专家内存隔离与消息投影将失效（抛出 `SHARED_MEMORY_ISOLATION_UNAVAILABLE`），且重新引入受限材料。**必须保留 `colink-harness[all]==1.0.7.post1` 补丁**，在上述能力未合入上游前保持阻塞。

### 2.2 Memory 补丁 (`colink-memory`)

1. **彻底物理遗忘与派生清理**：
   - Colink 要求支持 `Memory.forget_atom`、`Memory.atom_forget_ids` 及底层的 SQLite / PostgreSQL 物理删除机制。
   - 上游 1.0.5 核验结果：`forget_atom` 缺失 (`False`)，`atom_forget_ids` 缺失 (`False`)，后端删除逻辑缺失 (`False`)。
2. **防恢复持久化墓碑机制 (Tombstones)**：
   - Colink 的 `AtomForgetStore` 支持记录已被遗忘的 Atom ID 链条，防止管理员从旧备份还原数据时意外复活员工已要求遗忘的隐私数据。
   - 上游 1.0.5 核验结果：无墓碑支持。
- **结论与阻塞理由**：若直接替换为上游 1.0.5，记忆遗忘接口调用将直接触发 `RuntimeError: octop-memory does not provide permanent atom forgetting`，破坏数据安全合规能力。**必须保留 `colink-memory==1.0.3.post1` 补丁**。

### 2.3 分叉治理原则

Colink 品牌名仅用于组件清单与前端展示，不修改运行时模块导入名（仍为 `octop`）和命令行名称（仍为 `octop`），避免不必要的长期分叉。一旦上游官方接纳并发布同等能力的隔离与物理遗忘 API，Colink 将在通过平台回归后切回上游。

## 4. 内网裁剪清单与独立运行验证

为保证在断公网的企业内网环境中稳定运行，明确以下裁剪与隔离清单：

| 裁剪/隔离维度 | 裁剪对象 | 内网离线保障与验证方式 |
| --- | --- | --- |
| **公开市场** | 公网 `api.skillhub.cn` 与 `octop.cloud` | 默认关闭或支持配置为空；`portal_base()` 返回空时不发起外网请求。支持内网镜像重定向或纯本地内置技能/专家模式。 |
| **需公网登录连接器** | 公网 SaaS OAuth（飞书公网应用、Slack OAuth、公网邮件等） | 纯按需配置加载，不进入服务端核心引导生命周期；内网不配置时不产生网络请求与阻塞。 |
| **云主机控制与远端存储** | COS、S3、OBS、TOS 探针与云凭据检查 | 工作区默认使用本地文件系统 (`LocalStorageBackend`)；无云端凭据与外部网络时不阻断服务初始化与运行。 |
| **核心 Gateway 保留** | 内网 WebSocket 通信、本地设备控制通道 | 完整保留 Gateway 核心调度能力，支持内网飞书机器人防重 (`feishu_dedup`)、内网微信/QQ 表格降级与本地桌面设备配对。 |
| **受限材料剔除** | Harness 内置 PowerPoint 技能中的 51 个受限文件 | `scripts/strip_restricted_skills.py` 自动化裁剪；`tests/unit/test_release_skill_materials.py` 60/60 通过。 |
| **离线启动与服务持久化** | Greenfield 空数据目录启动与数据库绑定 | `tests/integration/test_offline_deployment_api.py` 覆盖空目录引导、向导密码、健康探针与重启持久化，通过验证。 |

## 5. 核验结论

1. **采用组合已锁定**：保持 `colink-harness[all]==1.0.7.post1`、`colink-memory==1.0.3.post1`、`octop-gateway>=1.0.3`、`octop-browser>=1.0.0`。
2. **两个 Colink 补丁保留理由明确**：已详细记录上游缺少动态隔离与物理遗忘 API 的实际缺陷，并在上游官方未补齐前保持分叉隔离；实机测试证明补丁功能完全正常。
3. **内网裁剪清单落实**：公网市场、公网 SaaS 连接器、云端存储探针不作为运行时硬依赖；受限 PPT 技能完全剔除；离线服务端启动与协议探针全部通过。
4. **无旧前置升级阻塞**：满足 Issue #31 的全部验收标准。
